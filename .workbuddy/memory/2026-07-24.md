# 2026-07-24 工作记录

## SSH 密码认证 — 终案：MSYS2 环境注入
- **经历了 6 轮调试**，确认 ASKPASS 机制本质正确，问题都在 Tauri tokio spawn 的 MSYS2 环境缺口
- **终案**：`.sh` + `#!/bin/sh`（标准 shebang）+ spawn 前注入 MSYS2 环境
  ```sh
  #!/bin/sh
  printf '%s' '密码'
  ```
  - **MSYS2 exec() 不支持 Windows 绝对路径 shebang**（`#!/c:/.../sh.exe` → `exec(): No such file`）
  - **Windows 绝对路径转换后也不行**（`#!/c/Users/.../sh.exe` 同样失败）
  - **只能 `#!/bin/sh`**，但需要 MSYS2 环境已初始化才能解析
- **注入方案**：spawn 前设置 `MSYSTEM=MINGW64` + PATH 包含 `ssh_bin.parent()`
  让子进程中的 `/bin/sh`、`printf` 等 MSYS2 路径可解析
- **ASKPASS 路径**也需从 `C:/Users/...` 转为 `/c/Users/...` MSYS2 格式
- Git Bash 验证成功：`ssh -o PubkeyAuthentication=no ... root@192.168.5.66 echo PING` → "PING"

  1. `echo` → 尾随 `\r\n` 污染密码

  6. `.sh` + `#!/bin/sh` + MSYS2 环境注入 → **当前方案**

## SSH ControlMaster 废弃 → 每次命令独立连接
- **问题**：`-N -M -S` ControlMaster 模式在 tokio spawn 环境中挂起（25秒超时），但直接 `ssh ... echo DIAG_OK` 密码认证成功
- **根因**：tokio spawn 的 Windows 子进程无 MSYS2 mount table，ControlMaster 持进程+轮询 socket 方案不稳定
- **修复**：完全废弃 ControlMaster 多路复用
  - `connect()` 改为直接执行 `echo PING` 验证认证（不 spawn，用 `.output()` 等待完成）
  - `ssh_run()` 每次命令独立创建新的 SSH 连接（设置 ASKPASS env vars，执行后断开）
  - `SshSession` 不再持有 `control_path`/`_child`，改为持有 `auth: SshAuth` enum（Password/Key/Agent）
  - ASKPASS 文件由 SshSession 生命周期管理（connect 创建，Drop 清理）
- **代价**：每次远程命令需完整 SSH 握手（LAN 环境约 <1s），从多路复用的 ms 级变慢，但可靠性优先
- 后续优化方向：稳定后可选连接池 / 批量命令合并

## 大文件打开性能优化（remote_open + open_local）
- **问题**：`remote_open` 用 `wc -lc` 遍历整个文件统计行数，`open_local` 全量字节扫描建索引，90GB 文件耗时数分钟
- **修复**：
  - `remote_open`：用 `stat -c%s`（O(1) 取大小）+ `head -c 8192` 采样首 8KB 估算平均行长 → 推算总行数（误差 <5%）
  - `open_local`：不再预建全量索引，改为懒加载 `RefCell<Vec<u64>>` 检查点；首次打开仅建第 1 行偏移，其余在 `read_local` 首次经过时按需构建
  - 总行数改用采样估算（`len * sample_lines / sample_bytes`）
- **效果**：文件元数据加载时间从 O(n)→O(1)，90GB 文件打开 <1s，后续滚动时按需构建检查点（每 4096 行一次微小延迟）
## 检索参数 `isRegex` 报错修复
- **现象**：检索时报错 `invalid args isRegex for command search: command search missing required key isRegex`
- **根因**：Tauri v2 默认会把 Rust 命令参数名按 camelCase 暴露给前端 invoke，Rust 侧参数名为 `is_regex`，前端应传 `isRegex`
- **修复**：`src/api.ts` 中 `searchLogs` 的 invoke 参数键从 `is_regex` 改回 `isRegex`
- 之前误判为应传 snake_case，改反了方向
